# M2 — сценарии исполнения стадии

Реальные сценарии для первого работающего цикла: **стадия 00 выполняется агентом и сохраняет BRD**.
Реализация пишется только под эти сценарии; тесты называются так же.

## Что именно запускается

`StageService.Run(pipelineID, targetSystemID, route, stageID)`:

1. берёт стадию из реестра (`domain.StageByID`) — маршрут принадлежит реестру, не агенту;
2. проверяет, что у владельца стадии есть валидный конфиг агента (`agent_configs`);
3. читает входные формы по `stage.Inputs`, берёт **последнюю версию** каждой;
4. собирает контекст: проекция полей по роли + инструкция стадии (компактный JSON, без истории);
5. просит модель вернуть payload выходной формы (`LLM.Complete`);
6. сдаёт форму через `FormService.Submit`: конверт, ссылки, гейты payload, hash;
7. при ошибке валидации возвращает её модели и повторяет (не больше 3 попыток);
8. записывает результат стадии (`StageRunRecorder`): `done`, `blocked` или `failed`.

Агент не выбирает следующую стадию, не читает БД и не пишет вне формы. Модель за портом `LLM`,
реальный адаптер (Ollama/OpenRouter) — этап M4 (шлюз моделей); в тестах — сценарный двойник.

## Happy paths

| # | Сценарий | Ожидание |
| --- | --- | --- |
| H1 | Есть `USER_INPUT`, агент `analyst` настроен, модель сразу отдаёт валидный BRD | BRD v1 сохранён в статусе `draft`, `StageRun.status=done`, попыток 1 |
| H2 | Модель сначала отдаёт BRD без целей, со второй попытки — валидный | BRD сохранён, попыток 2, и вторая попытка получила текст ошибки «goals» |
| H3 | Стадия 00 запускается второй раз, BRD v1 уже есть | сохраняется BRD v2 с `previousFormVersion` → v1 и hash предыдущей версии |

## Negative paths

| # | Сценарий | Ожидание |
| --- | --- | --- |
| N1 | Входной `USER_INPUT` отсутствует | типизированная ошибка `ErrStageInputMissing`, форма не сохраняется, запись о запуске не создаётся |
| N2 | У роли `analyst` нет конфига агента | `ErrAgentNotConfigured`, форма не сохраняется |
| N3 | Модель трижды отдаёт невалидный payload | `StageOutcome.Blocked=true` с тремя причинами, BRD **не** сохранён, `StageRun.status=blocked` |
| N4 | Адаптер модели возвращает ошибку (сеть) | ошибка наружу, `StageRun.status=failed` с её текстом |
| N5 | Неизвестный `stageID` | ошибка реестра стадий, ничего не записано |
| N6 | Модель отдаёт не-JSON (мусор) | считается провалом валидации, текст ошибки уходит модели, далее как N3 |

## Edge cases (отдаются независимому проходу)

| # | Сценарий | Ожидание |
| --- | --- | --- |
| E1 | Модель отдаёт пустой payload | провал валидации, а не паника и не пустая форма |
| E2 | Валидный payload приходит ровно на последней (третьей) попытке | успех, попыток 3, `done` |
| E3 | У `USER_INPUT` есть две версии (v1 и v2) | читается v2, ссылка в BRD указывает на v2 и её hash |
| E4 | Модель отдаёт BRD, где hash входной ссылки не совпадает | провал валидации «does not match», повтор |

## Что осознанно вне этого среза

- Реальный адаптер модели и квоты — M4.
- Создание формы `QUESTION` при блокировке: срез возвращает `Blocked` с причинами; превращение
  в `QUESTION` и ожидание оператора — следующий шаг (нужен HTTP и операторский контур).
- Стадии 01–06: их payload-гейты ещё не написаны, гейт вернёт «payload gates are not implemented».
- Хранение записей о запусках в БД: id пайплайна в формах — строка, в control plane — bigint.
  Порт `StageRunRecorder` строковый, адаптер к `runs` требует решения по id (см. отчёт).
