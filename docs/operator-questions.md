# Уточняющие вопросы оператору — спецификация среза

Статус: **спецификация, не реализовано**.
Основа: `Arhitecture.md` (stage 00 SysA), `form-registry/question.md`,
`form-registry/brd.md` (§Question rules), `implementation-plan.md` (D3, D4, D9).

## 1. Задача

Агент стадии, заполняя форму, может **вместо значения пункта** задать вопрос
оператору. Получив ответ, агент закрывает пункт и отдаёт формальный ответ.
Черновик становится валидным (`draft` → `valid`) без повторного допроса уже
закрытых пунктов.

Не-цели:

- не eino interrupt/resume (долгое ожидание не держит чекпоинт, D3);
- не второй формат «ответ = вопросы вместо формы» (он и порождает цикл, §3);
- не новая таблица под счётчики вопросов (§5);
- не управление циклом со стороны модели.

## 2. Пункт — единица работы

Пункт (`item`) — одно поле payload, у которого в реестре формы есть `Purpose`
и `Field` (см. `brd.md`). Ключ пункта:

- скаляр: JSON Pointer (`/metrics/0/unit`);
- элемент массива: `<array>[].id` + поле (`GOAL-1.outcome`), потому что индекс
  дрейфует при перестановке элементов.

**Набор ключей замораживается на первой сохранённой версии.** На повторном run
модель не может добавить или удалить элемент массива — только заполнить
открытые поля. Проверка: сравнение множества ключей с предыдущей версией.
Расхождение — protocol violation, штатный повтор через `maxTries`.

## 3. Протокол ответа модели

Один вызов модели возвращает и значения, и вопросы — по каждому открытому пункту:

| исход пункта | что в ответе | новое состояние |
| --- | --- | --- |
| `answer` | значение | `decided` |
| `ask` | вопрос + **свой предложенный ответ** + причина неуверенности + варианты | `questioned` |

`ask` обязан нести `proposal`: модель всегда сначала отвечает сама, а
уточнение — это подтверждение или поправка. Следствия:

- черновик формы всегда полный, дырок нет;
- после ответа оператора модели нечего додумывать — цикл не воспроизводится;
- «выдать вместо формы вопросы» — это вырожденный случай, когда все пункты
  `ask`. Отдельная ветка кода не нужна.

Право задать вопрос даёт гейт `domain.AllowAsk(itemKey)`, а не мнение модели
(D9). `ask` принимается только если:

1. у пункта нет принятого значения;
2. бюджет вопроса пункта не исчерпан;
3. в `ask` есть `proposal`, `reason` и хотя бы один `option`;
4. `pointer` не встречался в вопросах этой цепочки версий — это правило
   «no logical duplication» из `brd.md`, перенесённое в код: ключ дедупликации
   равен ключу пункта.

Иначе — protocol violation в `LLMRequest.Problems` и повтор (≤ `maxTries`).

## 4. Состояния формы

`domain` уже содержит `StatusDraft`, `StatusValid`, `StatusWaitingOperator`,
`StatusApproved`. Заполнение:

1. Гейт не прошёл → версия сохраняется как `draft` (сейчас N3 не сохраняет
   ничего, а `question.md` требует `formRef` на `draft`/`valid`).
2. Гейт прошёл → `valid`.
3. Есть блокирующий `ask` → `waiting_operator`, публикуется `QUESTION`.
4. Ответ оператора → новая версия (`previousFormVersion`), пункт `decided`.

**Требуется одна строка в `domain/form_status.go`:** `StatusDraft` должен
допускать `StatusWaitingOperator`. Сейчас `draft → waiting_operator` запрещён,
а обходной путь `draft → valid → waiting_operator` оставляет фиктивный `valid`.

## 5. Защита от бесконечных циклов

Три правила, все проверяемые кодом:

1. **Ответ оператора закрывает пункт навсегда.** Гейт замораживает значение
   `decided` пункта; модель не может переспросить даже если считает значение
   размытым.
2. **Бюджет пункта.** `maxRounds` (по умолчанию 1) — число раундов вопросов на
   пункт. Счётчик не хранится в новой таблице: он равен числу сохранённых
   QUESTION-версий, чьи `gaps[].pointer` указывают на этот ключ. Долговечно,
   переживает рестарт, нуля новых сущностей.
3. **Повторный run видит только открытые пункты.** `LLMRequest` получает
   `OpenItems` и `Decided`; решённые значения модель не переписывает.

Завершение: пусть `k` — число пунктов, `r` — `maxRounds`. Каждый операторский
раунд тратит бюджет одного пункта; бюджет монотонно растёт и ограничен `k·r`.
Значит раундов ≤ `k·r`, запусков стадии ≤ `k·r + 1`, вызовов модели
≤ `(k·r + 1)·maxTries`. При любом поведении модели.

Если модель упорно шлёт `ask` после бюджета, гейт отклоняет её `maxTries` раз,
стадия заканчивается `blocked`, пункт попадает в открытые пробелы.

## 8. Решения

1. **`maxRounds` = 1** (рекомендуется): ответ оператора финален. `2` даёт модели
   один переспрос, но и цикл ровно вдвое длиннее.
2. **Бюджет исчерпан:** принять последнее `proposal` и понизить пробел до
   неблокирующего (рекомендуется) либо оставить `blocking` и остановить
   маршрут. Первое не даёт опаздывающему оператору остановить пайплайн.
3. **Стык идентификаторов:** `domain.OperatorRequest.PipelineID` — `int`,
   `pipelineId` форм — строка. Тот же блокер держит `StageRunRecorder = nil`
   в `di`. Пока не решён, `Publish` не запишет `operator_request`.
