
| Концепция | Определение |
| --- | --- |
| **TargetObject** | Сущность с физической реализацией (файл, сервис, процесс, таблица). Может быть независимо задеплоена/изменена |
| **Поле** | Описание/свойство/атрибут объекта. Не имеет самостоятельной реализации. Живёт внутри другого объекта |
| **Проекция** | Не отдельная сущность, а **фильтр доступа**: роль агента определяет, какие поля объекта попадают в его контекст |
| **Кроссвладение** | = **RBAC для агентов**: инкапсуляция доступа к полям объекта относительно роли. Гарантирует предметность и формализацию инструкций |

| TargetObject | Физическая реализация | Пример |
| --- | --- | --- |
| **Контейнер** | Деплой-юнит, процесс, docker-контейнер | `user-service`, `api-gateway` |
| **Слой** | Структура пакетов в репозитории | `adapter/`, `domain/`, `infra/` |
| **Пакет** | Директория с кодом | `internal/auth/` |
| **Модуль** | Файл/группа файлов с конкретной ответственностью | `token_validator.go` |
| **Таблица / коллекция** | Реальное хранилище в БД | `users`, `sessions` |
| **Брокер / очередь** | Реальный инфраструктурный компонент | `rabbitmq`, `kafka-topic` |
| **Тест** | Файл с тестами в репозитории | `auth_test.go` |
| **Конфиг** | Файл конфигурации | `config.yaml`, `.env` |
| **CI/CD пайплайн** | Реальный процесс | `.github/workflows/build.yml` |
| **Окружение** | Реальная инфраструктура | `staging`, `prod` |
| **Документ-артефакт** | Файл в репозитории | `ADR-012.md`, `swagger.yaml` |
| **Aggregate** | **Поле Контейнера** | Не имеет самостоятельной реализации. Это логическая группировка модулей внутри контейнера. Реализация = набор модулей. Сам агрегат как файл/сервис не существует |
| **Bounded Context** | **Поле Контейнера** | Это граница/маркировка, а не артефакт. Реализация = контейнер(ы), которые входят в этот контекст. Сам по себе не деплоится |
| **Entity / VO** | **Поле Модуля** | В коде реализуются как структуры/классы внутри модуля. Не самостоятельный артефакт - файл модуля содержит и сущности, и логику |
| **DomainEvent** | **Поле Контракта** | Сообщение, не объект с состоянием. Реализация = структура в коде + конфигурация брокера. Живёт как поле контракта или как конфиг топика |
| **ADR** | **TargetObject** | Файл в репозитории. Физическая реализация есть |

### Итого: агрегация

```
Контейнер (TargetObject)
├── boundedContext: string          ← ПОЛЕ (маркировка)
├── aggregates: []Aggregate         ← ПОЛЕ (логическая группировка)
│     ├── rootEntity: string        ← ПОЛЕ (имя)
│     ├── entities: []string        ← ПОЛЕ (ссылки на модули)
│     ├── invariants: []string      ← ПОЛЕ (правила)
│     └── events: []EventMap        ← ПОЛЕ (описание)
├── layers: []Слой (TargetObject)
│     ├── packages: []Пакет (TargetObject)
│     │     ├── modules: []Модуль (TargetObject)
│     │     │     ├── contracts: []Contract   ← ПОЛЕ
│     │     │     ├── entities: []Entity/VO   ← ПОЛЕ
│     │     │     └── tests: []Тест (TargetObject)
│     │     └── connectedPackages: []ref
│     └── connectedLayers: []ref
└── relContainers: []ref
```

### Модель

```
Каждый Агент имеет Роль
Каждая Роль имеет набор Прав доступа к Полям объектов
Объект один, но агент видит только разрешённые поля
```

### Матрица доступа (поле × роль)

| Поле объекта | Архитектор | Аналитик | Разработчик | DevOps | QA |
| --- | --- | --- | --- | --- | --- |
| `container.purpose` | R/W | R/W | R/W | R | R |
| `container.boundedContext` | R/W | R | R | - | - |
| `container.aggregates` | R/W | R | R | - | - |
| `container.aggregates.invariants` | R/W | R | R | - | R |
| `layer.packages` | - | - | R/W | - | - |
| `module.code` | - | - | R/W | - | - |
| `module.contracts` | R | R | R/W | - | R |
| `module.tests` | - | - | R/W | - | R/W |
| `container.ports / deps` | - | - | R | R/W | - |
| `container.envConfig` | - | - | R | R/W | - |
| `test.scenarios` | - | R | R | - | R/W |
| `requirement.FRs` | R | R/W | R | R | R |
| `requirement.NFRs` | R/W | R/W | R | R | R |

> **R** = read, **W** = write, **-** = нет доступа (поле не попадает в контекст агента)
