System analiz

система должна представлять из себя Агентную систему на eino + опцциональные 

## 1. Нефункциональные требования 

### Вычислительные ресурсы

| Категория | Требование |
| --- | --- |
| **Локальные модели** | Система должна поддерживать **произвольное количество локальных моделей** с разными характеристиками: основная рабочая модель (напр., Qwen 3 Coder 30B, 20 req/s, 32k ctx), классификационные модели (напр., JEV-подобные), усиленные модели для сложных задач (напр., Qwen 3.7) |
| **Облачные модели** | 1000 запросов **в день** к бесплатным моделям через агрегаторы (с учётом разных лимитов у разных моделей), + для критичных задач бюджет $10/month |
| **Резервные модели** | Доступ к облачным моделям с медленной генерацией (напр., NVIDIA) как к резервным источникам без прямого бюджетного ограничения |

### Производительность и качество

| Категория | Требование |
| --- | --- |
| **Контекст** | Контекст каждой задачи должен быть **минимально необходимым и достаточным** для её исполнения. Предпочтение — компактным, хорошо структурированным контекстам |
| **Масштабируемость** | Система должна допускать горизонтальное масштабирование по стадиям и по агентам без перепроектирования |

---

## 2. Функциональные требования 

### 

0. Все операции между стадиями происходят языком ASD STE 100; слов недостаточно — вариативно Attempto Controlled English (ACE) и только ACE.
1. Система опперирует готовым инструментам и пакетам; авто-генерация модулей доккументации обязательна и LLM пишет код только в случае если задача не может быть выполнена без генерации.
2. При неопределенности агент обращается к оператору и переходит в состояние ожидания.
3. Оператор может прервать любой процесс.
4. У каждого агента прописаны доступные tools.
5. Максимальное переиспользование компонентов; штрафы за создание новых смысловых сущностей.
