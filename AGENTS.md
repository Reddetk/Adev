# adev — правила работы в этом репозитории

## Что это

adev — агентная система на Go + eino, которая строит софт по маршруту форм.
Документы: `../docs/SysReq.md`, `../docs/Arhitecture.md`, `../docs/implementation-plan.md`,
реестр форм: `../form-registry/`.

## Слои (Clean Architecture, каркас goca)

```
domain/      сущности, value objects, правила          — без I/O и context.Context
usecase/     сервисы, DTO, порты (интерфейсы)          — без SQL и HTTP
repository/  pgx-адаптеры, реализуют порты usecase
handler/     http / cli / worker адаптеры
di/          корень композиции
middleware/  http-middleware
```

Правила: новый код только в этих слоях. Самодельные пакеты вне слоёв не заводить.
Порт объявляет `usecase`; `repository` его реализует, а не наоборот.
Пакет `internal/constants` удалён — константы живут рядом с тем, кто их использует.

## Стек и запреты

- Хранилище — **PostgreSQL через pgx**. GORM, `lib/pq`, `go-sql-driver/mysql`, `sqlite` удалены.
  Не возвращать их. Запросы только параметризованные (`$1`, `$2`).
- Провайдер агента `opencode` — OpenCode Console (OpenAI-совместимый chat completions):
  база `https://opencode.ai/inference/openai/v1`, ключ — на `opencode.ai/console` (вход, баланс, «copy API key»),
  заголовок `Authorization: Bearer <ключ>`. Модели ставятся по id из `https://opencode.ai/inference/v1/models`,
  например `glm-5.3-flash` (платная, нужен баланс в консоли). Модели с суффиксом `-free` через API не работают:
  OpenCode отвечает 403 `FreeTierError`, бесплатный тариф только внутри клиента OpenCode.
- Миграции — golang-migrate, файлы `migrations/NNN_name.up.sql` / `.down.sql`, нумерация только вперёд.
  Применять: `make migrate-up`. Схему не менять через код.
- Домен, репозитории и usecase сгенерированы `goca`; правки в них делать в стиле окружающего кода.

## Makefile — точка входа

```
make help          список целей
make build / test / vet / fmt
make dev-db        поднять БД и дождаться healthcheck
make migrate-up    применить миграции
make run           запустить сервер с настройками из .env
make tools         поставить migrate, golangci-lint, gosec, swag
make ui-install    npm install в ../frontend, один раз после клона
make ui-dev        Vite на 5173, проксирует /api на сервер
make ui-build      собрать ../frontend/dist, make run отдаёт его на /app/
```

`make` доступен через WinGet Links. `make test-race` требует cgo.

Локальный запуск GitHub Actions через act:

```
make act-image            один раз собрать образ раннера (~700 МБ)
make ci-act-dry ACT_JOB=unit    план без контейнера
make ci-act ACT_JOB=unit        тот же job локально, ~80 с
```

Образ обязателен: образ act по умолчанию без git, без корневых сертификатов и без gcc.
`ci-act` сам переходит в корень репозитория, потому что workflows и `.actrc` лежат там, а не в `adev/`.
Postgres-job может попасть в ваш Postgres на 5432: запускайте его только когда там тестовая БД,
либо используйте `make ci` и `make test-db`.

## Frontend

UI оператора — React + TypeScript + Vite в `frontend/`, рядом с модулем Go. Три вкладки:
«Target System» (обзор системы: FR/NFR из SRS, Context Map, агрегаты и инварианты, стратегия
деградации из HLD + карта компонентов C4: контейнер = Container, слой = Layer, пакет = Component,
модуль = Code; наведение — назначение, правый клик — контракт), «Пайплайн» (цепочка агентов:
схема стадий с документами, живые карточки прогонов с историей вызовов к модели
(`GET /modelcalls`) и кнопкой остановки (`POST /runs/stop`), вопросы оператору)
и «Настройки» (targetSystem, workspace, агенты, проверка модели, готовность и план).

- Типы в `frontend/src/api.ts` повторяют DTO Go; единственный HTTP-слой, каждый запрос
  попадает в журнал — по нему и отлаживаем.
- Внизу экрана сворачиваемая панель: «Журнал запросов» (что сделал браузер) и «Логи сервера»
  (что написал сервер, `GET /api/v1/logs`, опрос раз в 5 секунд).
- «Вопросы» читают `GET /api/v1/operatorrequests` и опрашивают его раз в 10 секунд.
  Ответа из консоли пока нет: endpoint ответа — срез Q4 в `docs/operator-questions.md`.
- Разработка: `make ui-dev` → http://localhost:5173, Vite проксирует `/api` на :8080,
  поэтому CORS не нужен. Сборка: `make ui-build` → `frontend/dist`, `make run` отдаёт её на `/app/`.
- Библиотеки без нужды не добавлять: роутер, UI-кит и кеш запросов — когда экранов станет больше.

## Логи

- `logger.Init` пишет каждую строку в stdout, в кольцо в памяти (500 строк, оттуда
  их читает консоль) и в файл `logs/adev.log` (путь меняется через `LOG_FILE`).
  Файл нужен потому, что фоновый процесс без консоли иначе не оставляет следов.
- `middleware.Logging()` навешан один раз на `/api/v1`: раньше его копии стояли
  только на сгенерированных goca-роутерах, и запросы к формам, настройкам и
  стадиям вообще не логировались.
- `usecase.StageService` пишет строку на каждую серию попыток стадии: статус,
  число попыток и причину отказа модели или гейта.
- `make logs` следит за файлом.

## Формы

- Источник правды — markdown в `../form-registry/`. Runtime-типы — `internal/forms`.
- Конверт обязателен: `formId`, `formType`, `formVersion`, `status`, `mode`, `inputs`, `payloadHash`.
- Форма неизменяема после `approved`. Исправление — новая `formVersion` с `previousFormVersion`.
  Пока форма ждёт оператора (`waiting_operator`), ответ оператора переписывает её payload на месте, без новой версии.
- Delta — `mode: "delta"` + JSON Patch (RFC 6902), не новый тип формы.
- Агент сдаёт форму инструментом, а не текстом. Любой ответ модели принимается: несоответствие форме
  сохраняется на черновике как индикатор, а переген или ответы на вопросы решает оператор. Авто-починки
  через повторные вызовы нет, это экономия токенов.
- Свободный текст только в `Text`/`Statement`/`Scenario`; язык ASD-STE100/ACE.
- `objectId` из реестра объектов, а не путь, для всего, что уже существует.

## Пайплайн

- Стадии и владельцы — `internal/pipeline/stages.go`. Маршрут принадлежит реестру, **агент не выбирает следующую стадию**.
- LLD растёт деревом, один уровень за проход: первый ответ — только список верхнего уровня,
  дочерние списки пустые; затем каждый элемент получает отдельный вызов на свой список
  (`containers` → `layers` → `packages` → `modules` → `deps`). Пустой дочерний список —
  заказ следующего прохода, а не `openGaps`.
- Стадия не стартует без готовности: workspace + валидный конфиг агента на каждую роль (`internal/settings`).
- `apiKey` не покидает сервер: `json:"-"`, в ответах только `hasApiKey`.
- Запуск стадии (`POST /stages/{stage}/run`) отвечает 202 сразу: цепочка агентов работает в фоне
  (`usecase.StageRunService`), состояние — в таблице `runs` (running → done|blocked|failed|stopped).
  Закрытая вкладка и HTTP-таймаут прогон не отменяют (`context.WithoutCancel`); при старте сервер
  возобновляет прогоны со статусом `running` строки которых остались от прошлого процесса (Resume).

## Проверка изменений

```
make fmt && make vet && make test
```

Postgres-тесты включаются только переменной `ADEV_TEST_DATABASE_URL` на отдельную тестовую БД:
они делают `TRUNCATE forms`, и на dev-БД из `.env` их запускать нельзя.

## Работа с оболочкой

- **Приоритет инструментов.** Для поиска по коду используй `functions.grep` и `functions.glob`. Для чтения файлов — `functions.read`. Не используй shell для того, что можно сделать этими инструментами.
- **Windows-окружение.** Среда win32. Типичные GNU-утилиты (`grep`, `sed`, `awk`, `head`, `tail`, `wc`, `xargs`, `find`) могут отсутствовать. Не вызывай их по умолчанию.
- **Только нативное в shell.** Если без shell действительно не обойтись — используй только нативное для Windows: `dir`, `findstr`, `where`, PowerShell cmdlets. `findstr` работает иначе, чем `grep`, не используй Unix-синтаксис.
- **Не циклись.** Если shell-команда завершилась ошибкой `не является внутренней или внешней командой` или похожей — **немедленно** переключайся на `read`/`grep`/`glob`. Не меняй одну и ту же команду по мелочи и не вызывай её десятки раз.
- **Меньше конвейеров.** Избегай сложных цепочек `cmd1 | cmd2 | cmd3`. Они избыточны и ломаются в этой среде.

## Правила ответа

- Минимальная правка, которая полностью решает задачу. Без абстракций «на будущее».
- Не добавлять зависимость без обоснования.
- Комментарий — только там, где код не объясняет «почему».
- Известное ограничение помечать `shortcut: <ограничение>, <когда исправлять>`.
